The error **"Failed to launch JVM"** during or after installing a Windows application from an **MSI** package usually means the application cannot start the Java Virtual Machine. The cause depends on whether the app bundles Java or expects Java to be installed separately.

Here are the most common fixes, in order.

### 1. Check if Java is installed
Open **Command Prompt** and run:

```
java -version
```
If you get:

```
'java' is not recognized...
```
then Java is not installed or is not in your PATH.

---

### 2. Install the correct Java version
Many Windows desktop applications require a specific Java version (often Java 17 or Java 21).

Check the application's documentation to see which version it needs.

---

### 3. Check if you're using the correct architecture
Make sure these match:

- 64-bit Windows → 64-bit Java
- 32-bit Windows → 32-bit Java
A mismatch can cause JVM launch failures.

---

### 4. Check the JAVA_HOME variable
Run:

```
echo %JAVA_HOME%
```
It should point to something like:

```
C:\Program Files\Java\jdk-21
```
Then verify:

```
%JAVA_HOME%\bin\java.exe -version
```

---

### 5. Check the PATH variable
Run:

```
where java
```
Example output:

```
C:\Program Files\Java\jdk-21\bin\java.exe
```
If nothing appears, add Java's **bin** folder to your PATH.

---

### 6. Run the application as Administrator
Sometimes the launcher cannot access required files without elevated permissions.

---

### 7. Check antivirus
Windows Defender or another antivirus may quarantine:

- `jvm.dll`
- `java.exe`
- `javaw.exe`
Restore them if necessary.

---

### 8. Reinstall the application
If the MSI bundles Java, the bundled runtime may have failed to install.

Uninstall the application, reboot, then reinstall.

---

### 9. Check Event Viewer
Open:

```
Win + R
eventvwr
```
Go to:

```
Windows Logs
    → Application
```
Look for Java or application errors.

---

### 10. If this is a Launch4j application
Many Windows Java apps use **Launch4j**.

The error may actually be:

```
Failed to launch JVM
```
This usually means:

- JVM not found
- Wrong Java version
- Corrupted Java installation
- Missing `jvm.dll`

---

## If you're building the MSI yourself
If you're creating the MSI using:

- WiX
- Advanced Installer
- Inno Setup
- jpackage
- Launch4j
the problem may be that:

- the bundled JRE wasn't included
- the MSI can't locate the runtime
- the install path is incorrect
- the launcher points to the wrong JVM location
